# مراجعة Baseera — 26 أكتوبر 2026

المراجعة تخص نسخة التطوير `0.5.0-preview` على جهاز Windows x64 واحد، وتشمل
قراءة الشيفرة، اختبارات الوحدات، الواجهة والحزمة، وقراءات أصلية من ويندوز.
لا تعني اجتيازها ضمان غياب الأخطاء أو اعتماد التوافق مع كل أجهزة Windows 10 و11.

## الأخطاء التي عُثر عليها وأُصلحت

1. **تعطل تعداد نتائج WMI:** استخدام مجموعة نتائج `ForwardOnly` مع محول
   `IEnumerable` لواجهة WMI البرمجية سبّب `DISP_E_EXCEPTION` أثناء التعداد،
   حتى مع استعلام نظام بسيط. كان هذا يُخفي معلومات التعريفات وبعض معلومات
   الأمان وUSB. أُعيد إنتاجه فعليًا بمقارنة الأعلام 0 و16 و48؛ نجح 0 و16 وفشل
   48. استُخدم 16 مع الحفاظ على حدود وقت وذاكرة العملية الفرعية. بعد الإصلاح
   أعادت التجربة المجمعة النهائية 18 معلومة للتعريفات و9 للأمان و5 لـUSB؛ بقيت المصادر
   الناقصة موسومة بحدودها، دون طلب صلاحيات إضافية.
2. **استبعاد مسارات Cloud Files المتاحة محليًا:** كان كل `ReparsePoint` يُعامل
   كرابط، بما فيه عناصر OneDrive العادية. أصبح التمييز يعتمد على وسم ويندوز
   الأصلي، مع قبول وسوم Cloud Files المعروفة فقط. تبقى الروابط والوسوم
   المجهولة مستبعدة، وتُتجاوز العناصر التي تحتاج استدعاء المحتوى من السحابة.
   أُضيفت اختبارات للوسوم الستة عشر وحالات Offline/Recall، مع قراءة وفحص
   ملفات مصدر فعلية. توضح [وثائق Microsoft للوسوم](https://learn.microsoft.com/en-us/windows/win32/fileio/reparse-point-tags)
   سبب عدم مساواة جميع نقاط إعادة التحليل بالروابط.
3. **عرض DNS مضلل عند إدخال IP مباشر:** كان الوقت المحلي لمعالجة العنوان
   يظهر كزمن DNS. يُستخدم العنوان مباشرة الآن ويظهر أن استعلام DNS غير مطلوب؛
   لا يُفسَّر عدم وجود هذا القياس كفشل DNS. شمل ذلك نصوص اللغات الأربع واختبار انحدار.
4. **إمكان تغيّر الملف بين البصمة والتوقيع:** كان حساب SHA-256 والتحقق من
   Authenticode يفتحان الملف في فترتين منفصلتين. يُحتفظ الآن بالمقبض نفسه دون
   مشاركة الكتابة أو الحذف حتى اكتمال العمليتين. اختبار فعلي حاول الكتابة
   والاستبدال في المنتصف، وأكد رفضهما وبقاء البصمة صحيحة. يعالج الاختبار
   صيغتي رفض المشاركة ورفض الوصول اللتين قد يعيدهما ويندوز.
5. **ترتيب العدّادات في العربية:** أظهرت مراجعة اللقطات أن القيم مثل `3 / 6`
   قد تنعكس بصريًا في RTL. استُخدمت عبارات مترجمة مثل «3 من 6» لردود الشبكة
   وعدّاد المراقبة، وعبارة صريحة لعدد نتائج الاشتباه من الإجمالي في فحص السمعة.
6. **توثيق قديم:** صُححت عبارة عدم وجود تبعيات ومسارات بناء الإصدار القديم
   في README باللغات الأربع؛ أُضيفت أوامر الاختبارات الأصلية وحدودها.

## إعادة الاختبار

نجح البناء دون أخطاء أو تحذيرات، و275 اختبارًا أساسيًا، وخمسة اختبارات لإضافة
المتصفح، واختبار سياسة التوقيع. نجحت جولة الحزمة الكاملة (58 عرضًا أساسيًا
و32 عرضًا للمراكز)، والاختبارات الأصلية الإحدى عشرة من EXE المستقل.
أُعيد اختبار المراكز بعد تصحيح العدّادات. اختبار إنشاء رابط رمزي في بعض
اختبارات الوحدات يُتجاوز صراحة عند غياب صلاحية إنشاء الروابط.

نجح التحديث الفعلي من نسخة `0.4.15` معزولة إلى نسخة التطوير الحالية، مع
الاحتفاظ باسم EXE المخصص وبايتات الإعدادات والأسرار. ونجح التراجع إلى النسخة
السابقة عند إغلاق نسخة الاختبار قبل تأكيد جاهزيتها، ثم تنظيف ملفات الاسترداد.
استُخدمت نسخ مؤقتة فقط، ولم يُستبدل تطبيق مثبت للمستخدم.

```powershell
./build.ps1 -Test -Publish
./build.ps1 -Smoke
./tests/windows/Test-ReadOnlySystem.ps1 -ExecutablePath artifacts/Baseera.exe
./tests/windows/Test-ReadOnlySystem.ps1 -ExecutablePath artifacts/Baseera.exe -AllowNetworkCheck
./tests/self-update.e2e.ps1
./tests/windows/Test-SigningPolicy.ps1
node --test extension/test/protocol.test.js
```

الاختبارات الأصلية اختيارية ومنفصلة عن اختبارات البيانات النموذجية. تحفظ
ملخص أعداد وتوافر المصادر فقط، دون أسماء النوافذ أو البرامج أو محتوى السجلات.
لا يشغّل مسارها إصلاحًا أو تنظيفًا أو ترقية تطبيق أو طلب ذكاء اصطناعي أو تسجيل صوت.
بعض معلومات الأمان والتعريفات قد تبقى جزئية بسبب الصلاحيات أو حدود جمع البيانات.

فحص NuGet المباشر والمتعدي لم يعثر على ثغرات معلنة في المصدر وقت المراجعة.
هذا لا يثبت خلو التبعيات أو التطبيق من ثغرات غير معلنة. يبقى EXE غير موقّع
لعدم توفر شهادة ناشر، وتبقى نسخة التطوير منفصلة عن الإصدار العام المنشور.
